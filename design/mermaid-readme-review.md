# Nibmark — Mermaid README 검토 및 착수 준비 상태

검토일: 2026-11-15 (Asia/Seoul)

후속 결정: 사용자가 개인 Public 저장소, MIT 라이선스, 별도 작업 폴더를 선택했다. 저장소는 jhbrunokim/nibmark, 로컬 폴더명은 nibmark로 초기화한다. 아래 준비 상태 표와 미정 항목은 이 결정 전의 검토 기록이다.
대상: [mermaid-js/mermaid README](https://github.com/mermaid-js/mermaid/blob/develop/README.md)
저장소 메타데이터에서 기본 브랜치가 develop임을 확인하고 해당 README를 읽었다. 아래 Mermaid 관련 관찰은 README에 대한 것이며 소스 코드 구조를 분석한 결과는 아니다.

## 1. 참고할 구성과 Nibmark의 적용

| Mermaid README에서 확인한 구성 | Nibmark에 적용할 방법 | 현재 반영 |
| --- | --- | --- |
| 제품명과 짧은 설명 | Nibmark / Give your project a nutrition label. | README 초안 |
| 상단 Live Editor 진입점 | 출시 후 첫 행동을 편집기 열기로 제시 | 편집기 공개 전까지 링크를 만들지 않음 |
| 문서·시작 안내·통합 링크 | 설계 명세, 예제, 이후 실제 사용 가이드로 연결 | 존재하는 문서만 연결 |
| 소스 문법과 렌더링 결과를 함께 배치 | 문법과 그에 대응하는 라벨 시안을 함께 표시 | 가상 수치 128개 예제와 SVG |
| 텍스트 기반 문서와 버전 관리의 장점 | 라벨 정의를 텍스트 파일로 보관하고 변경 사항 검토 가능 | 제품 원칙에 반영 |
| 다양한 예제 및 예제별 편집기 링크 | 출시 시 기본·한국어·0개 의존성 예제를 제공 | 구현 후 추가; 현재 종류는 nutrition 하나 |
| README에서 Live Editor·CLI 등 관련 프로젝트 소개 | 렌더링 코어를 UI와 분리해 나중에 CLI/통합으로 확장 | 구조 제안; 당장은 저장소 하나 |
| 시각적 회귀 테스트 도구 소개 | 라벨 모양 변화, 한글 줄바꿈, 내보내기 결과를 이미지로 검증 | 완료 기준과 초기 구현 계획 |
| 사용자 입력의 안전한 렌더링 설명 | 문자열을 텍스트로 처리하고 SVG에 실행 코드·외부 리소스를 넣지 않음 | 기존 명세 유지 |
| 기여 안내·라이선스·배포 설명 | 작동하는 개발 명령과 실제 라이선스를 준비한 뒤 공개 | 라이선스 결정 및 구현 후 검증 필요 |

Mermaid의 배지·후원·커뮤니티 규모·지원 도표 수는 성숙한 프로젝트의 현재 상태다. Nibmark README에는 실제로 존재하는 기능·링크·검증 결과만 넣는다. 현재 결과 이미지는 정적 시안임을 명시했다.

## 3. 구현 초기에 검증할 불확실성

1. **서체와 밀도:** 참조 라벨의 초굵은 제목, 숫자와 문자의 폭, 행 간격을 고정된 글꼴 환경에서 재현할 수 있는지 확인한다. 시안 승인과 실제 렌더링 확인이 필요하다.
2. **SVG 글꼴 호환성:** GitHub의 이미지 표시와 브라우저에서 글꼴이 대체될 때 줄바꿈이 변할 수 있다. 텍스트 SVG/윤곽선 방식의 품질·접근성·용량을 초기 실험에서 비교한 후 결정한다. 최종 배포 글꼴의 라이선스를 확인한다.
3. **PNG 출력:** 한글 글꼴 로딩 완료 후 내보내기, 굵은 선과 텍스트 누락 여부, 미리보기와 결과 일치를 확인한다.
4. **사용성:** 예제를 처음 연 사용자가 이름·수치를 수정해 이미지를 얻을 수 있는지 확인한다. 오류 상태에서 이전 미리보기가 현재 입력처럼 보이지 않아야 한다.

이 항목들은 구현 전에 모든 답을 추측해 확정하기보다 첫 번째 작은 렌더링 실험으로 검증하는 편이 적절하다. 핵심 수치나 제품 목적을 다시 정할 필요는 없다.

## 4. 첫 구현 단계 제안

### 단계 A — 렌더링 검증

- 명세를 파서가 처리할 수 있는 형태로 옮기고 문법 위치 정보를 유지한다.
- 하나의 예제로 본문 → 모델 → SVG의 전체 경로를 작동시킨다.
- 원본 레이아웃과 비교하고 영문/한글 글꼴 및 PNG 출력 방식을 검증한다.
- 이 단계의 결과로 디자인 재현 가능성과 내보내기 방식을 결정한다.

### 단계 B — 웹 편집기

- 실시간 편집, 오류 표시, 기본/한국어/0개 예제를 제공한다.
- 문법 저장·불러오기, SVG·PNG 다운로드, Markdown 이미지 삽입문을 연결한다.
- 프레임워크와 무관한 코어를 유지한다.

### 단계 C — 첫 공개 버전

- 실제 실행으로 개발·빌드 명령을 검증하고 README에 반영한다.
- 선택한 라이선스, 기여 안내, 확인된 지원 환경과 제한을 문서화한다.
- 승인한 공개 환경에서 배포하고 실제 주소를 README에 연결한다.

추천 초기 구성은 저장소 하나 안의 `src/core/`, `src/editor/`, `examples/`, `tests/`, `docs/`다. 이는 Nibmark를 위한 제안이며 Mermaid 저장소 구조를 조사해 복제한 것이 아니다. CLI·SBOM·문서 플러그인은 첫 버전 이후로 유지한다.

## 5. GitHub 등록 전에 필요한 결정

- 저장소 이름 제안: `nibmark`.
- 소유자: 개인 계정 또는 지정한 조직. 아직 미정.
- 공개 범위: Public 또는 Private. 공개 사용·기여를 목표로 하지만 최초 공개 시점은 사용자 결정.
- 라이선스: MIT를 후보로 제안하되 사용자 선택 전에는 LICENSE 파일을 생성하거나 MIT라고 표시하지 않는다.
- 등록 대상 파일: README, 설계 문서, 직접 작성한 시안. 이 단계에서 원본 첨부 이미지를 공개 저장소에 추가하지 않는다.
- 로컬 위치: 현재 학습 폴더를 사용할지 별도 Nibmark 프로젝트 폴더로 옮길지 등록 전에 확정한다.
- 사용자의 개발 착수 승인: 기존 요청에 따라 아직 대기 중이다.

이번 검토에서는 문서만 작성했다. 저장소 생성·커밋·푸시·공개 배포·npm 게시·앱 구현은 수행하지 않았다.
